# 学术写作心得

## 可快速查阅的Summary

> 让AI阅读论文梳理逻辑时，与其让它直接描述做什么方法，不如引导它描述为什么会有这种方法，这种方法怎么就能解决问题。

**论文精读/论文写作的逻辑**
- **标题**：精读标题的每个关键词，提取出它想解决什么问题，怎么解决问题，有它没它有什么区别。然后给出一句话概括标题（即写个TL；DR）
- 这篇文章的基本信息和发布时间线：有没有开源代码，什么时候开源的，开源后有没有宣传；文章什么时候投稿，什么时候被接收
- **作者和单位**：搜索每个作者在网上的公开资讯和个人博客，特别关注它们声称致力于做什么，之前有没有知名的相关工作
- **摘要和关键词**：copy一份，然后从里面提炼出主要问题、相关工作局限性、核心思想、方法实现、实验结果
- **目录和章节组织**：把章标题、节标题和小节标题都做个汇总，然后简短介绍下目录组织架构和不同章节之间的关系，比如方法部分是先overview再依次呈现具体模块，还是先理论分析再系统实现，等等
- **背景**：结合目录分析背景部分介绍了哪些，为什么它要介绍这个，是划定了要解决的问题，给出了现在依托的方法，点出了场景的特殊性，阐述了当前痛点和已有工作的局限，还是支撑了论文哪一段核心论证
- **动机**：如果说现有方法存在性能劣化，要突出这样性能劣化反映了怎样可见的风险，这个定量怎么就导致定性了
- **方法**：每个图表和伪代码都分别阐述，包括方法框架图、代码变换通路怎样
- **实验**：每个图表都分别阐述，包括验证哪几个问题，实验设计的硬件平台、基线选择、评估方法和性能指标，结果分析的定量提升、消融实验
- **相关工作**：跟哪些相关工作产生了联系，怎么界定本研究的贡献范围
- **讨论**：对未来领域的指导意义，最有影响力的工作如何，你当前的影响力如何，列举你的技术贡献，后续有哪些工作
- **总结**：从审稿人的角度做个点评

**论文粗读/开题报告的逻辑**
- **Goal（主要场景）->Challenge（关键挑战）->Insight（核心优势）->Contribution（预期效果，时间安排）**
- 主要场景：这个方法描述完了有什么好处，用户是谁。先画好这个饼，再谈技术选型。技术上的好处不能当做是用户得到的好处
- 关键挑战：硬骨头在哪里，缺少什么才导致了什么
- 核心优势：你有什么洞察，你提出了什么核心思想，为什么是你来做
- 预期效果：最后做成的系统是怎样子的，输入什么，输出什么；领域内的SOTA是谁，怎么跟它比
- 时间安排

**制作PPT的原则**
- 每页PPT的文字只需大标题、小标题、两三句bullet sentence。一页ppt最大可能减少信息量，不讲技术细节，讲清楚 so what
- 突出一句话的takeaway和与上一页的联系，每页间要有引导，演讲时娓娓道来
- 呈现例子要找一个“大家一下就明白”的展示点，一个具体、可量化、可展示的成果实例

## 写在前面

研究生期间接触到了专利、基金/开题报告、毕业论文等文书的写作。在我看来，研究成果的书面表达，就是按顺序由浅入深地经历了（一）拿具体成果写专利、（二）撰写基金/开题报告、（三）整理成毕业论文、（四）总结成简历和研究陈述这些流程。在这个过程中，思考方式经历了从描述具体成果、确定研究方向到准备汇报演讲这样由具体到抽象、由面向技术到面向观众的转变。

## 一、拿具体成果写专利

专利（特指发明专利，是一项发明描述书）是：与现有工作相比，有non-trivial的独特之处，使得性能指标有提升的一套方法论。
- 介绍现有工作相当于介绍领域背景、要解决的任务和当前挑战（反映为某个性能指标不够好），呈现作为对照组的方法论。
- 介绍独特之处相当于介绍改进的动机和核心思想（表明这是non-trivial的），呈现作为实验组的方法论，量化它相比对照组能带来的性能指标提升。
- 这套方法论具体采用什么技术路线、怎么写代码实现、怎么设计实验验证等可以很开放（它们只是方法论的一种实例化），只要能支持现有工作和独特之处的论述即可。

## 二、为成果撰写基金/开题报告

基金、开题报告的框架本质上是项目申请书，需要讲明白为什么要做一个项目（即立项依据），打算怎么开展（即研究路线）。
- 立项依据就是领域背景、要解决的任务和当前挑战（跟专利强调最相关的现有工作相比，基金强调有充分文献支持的国内外研究现状）。
- 研究路线就是针对当前挑战，提出框架级总体研究目标（跟专利一样要体现出独特之处），下面分模块级研究内容，它们采用工具级技术路线实现。
- 从立项依据到研究路线、从研究路线里的宏观级别到微观级别的逻辑，以及研究路线里同级别的关系，要高度统一。

## 三、整理成毕业论文

### 取标题的艺术

| 标题种类            | 要点                       | 标题示例      |
| --------------- | ----------------------------------- | --------- |
| 新方法完成旧任务 | 为啥旧方法不够好，为啥新方法有望解决（跟写专利很像）          | 《基于XXX方法的XXX任务研究》 |
| 旧方法用在新场景上       | 新场景有什么特殊性，这个特殊性导致直接用旧方法会有哪些挑战，怎么解决的 | 《面向XXX场景的XXX方法研究》 |
| 提出一个总体研究目标  | 为什么要研究这个，包括哪些研究内容，它们之间有什么关系（跟写基金很像）     |《Scalable and Intelligent Learning Systems》，Tianqi Chen，2019  |
| 前沿方法论的实践经验      | 科普这个方法论，讲如何在这个方法论下做相关实践            | 《Deep Learning for Compilers》，Chris Cummins，2020  |

上面四个标题种类中，前两个常见于硕士论文（要专而精，避免像一本书的标题），后两个给的示例都是博士论文（要提炼出共性）。

取标题事实上关乎着读博期间的方向选择。在AI推理优化和AI4Tuning中有两个大方向，呼应了上述标题种类：
- 利用【新硬件特性】，在【AI推理通路】中完成【某一维度（算子融合、异步、layout推导、跨层协同）】的【未优化->手写优化->自动优化->统一表示成IR和DSL】。需要思考：这个新场景怎么冲击原有的全栈流程？
- 利用【最新AI方法】，赋能【AI编译调优】中的【某一维度（准确表示、高效搜索）】的【从规则式到 the bitter lesson 式】。需要思考，这是不是一个适合给AI解决的好问题？

新场景才有新问题，新方法才值得新尝试（至少能讲故事）。就算卷旧问题旧方法的改进，也要卷那种，问题是重要问题，方法的改进有很大收益的。

### 撰写论文

**摘要写作逻辑**
- 第一段，开头要有个“近年来”，
- 第二段，开头要有个“然而”，后面要出现“一方面，现有方法不能”，“另一方面”，
- 第三段，“针对上述问题，本文从XXX和XXX两方面进行研究，创新性地提出了XXX方法和XXX方法，并在此基础上实现了XXX平台，具体内容包括：”
- 第四段到第六段，“在XXX方面，提出了一种XXX方法。”然后描述该方法的细节，后面要出现“（在XXX数据集上的）实验结果表明，XXX相比现有方法提升XXX”
- 关键词四个，从大主题到小主题

**绪论写作逻辑**
- 是上述“论文精读/论文写作的逻辑”的凝练

**方法写作逻辑**
- 一个方法对应一个主要问题，一个主要问题存在两个技术挑战，两个技术挑战对应两个具体方法，且这两个方法是串起来的（如方法二在方法一的基础上实现）

**正文润色逻辑（一份自检清单）**
- [ ] 选题背景要把概念讲清楚，包括要解决的任务和依托的方法。
- [ ] 存在问题关注有哪几个，每一个对应本文工作的一个贡献点；通过实验数据和直观图表来揭示这个问题及导致的性能后果。
- [ ] 研究现状关注分成了哪几类，跟本文工作最相关的是哪类，用发展历程串起来；每类最后给个优缺点的总结。相关工作，是用来界定贡献范围和创新点的。
- [ ] 研究内容关注动机（哪里需要改）->预实验数据得出结论（不改的话性能上不去，性能差距反映成可见风险）->启发（可以这么改，理论分析这么改是有效的）->方法（具体怎么改）->实验验证方法效果（这么改真的有用，提升可量化）
- [ ] 方法部分要说算法有算法图，说框架有框架图。术语引入的义务。
- [ ] 方法部分的数据，到底什么程度，从常识来看如何。数据引入的义务。
- [ ] 实验设置中，优化对象，比较方法，评估指标，实验平台都要解释清楚。
- [ ] 润色正文，每个地方反反复复穿插着提自己的创新点

**书面表达原则**
- 论文写作的不同部分是给不同的人看的，所以不同部分会有不同打磨
- 论文有很多种故事的写法，挑选最有趣的，the widest implication，the biggest question，the most fundermental new understanding
- 论文图表颜值始终要高。句子中总分总一直适用。be formal, fluent, engaging就不用说了
- 要能看到全文中宏观和微观的connection，从标题开始到摘要到全文
- 对每个部分的要求：
	- **background & motivation**，第一句要非常general。然后由浅入深 (proceed from the elementary to the profound.)，从通用到具体、从以前到现在、从问题到方案等都能看出过渡
	- **gap in the literature**，清楚点出
	- **method & result**，做了什么，结果->结论->新理解
	- **discussion & conclusion**，先总结下result和结论，突出与其它工作的对比，后面要讨论局限性，最终迈向新理解：a broader perspective, how your new understanding can provide explanations for unrelated system。

<!-- ### 答辩自检清单

> 听了三天师兄师姐们毕业答辩，梳理了答辩过程中评委一般会问的问题。核心是要让评委很容易听明白你的工作。

**论文立意**（工作有意义）

- [ ]  研究问题能用一句话说明在什么场景下解决什么（输入什么，输出什么），提升了什么指标
- [ ]  研究意义/关键挑战能让外行人一看就懂（通过小例子或描绘应用前景），知道选定的场景跟其他场景相比有什么突出的难点、特殊性和研究价值
- [ ]  研究现状讲现在解决到什么程度（是现有方法在某个阶段难以自动化，还是SOTA性能仍达不到某个阈值）
- [ ]  研究内容应具体、量化、可拓展；不要有歧义，不要看起来大包大揽结果虎头蛇尾没有闭环（有多大能力就画多大的圈）。最好是能给个case study
- [ ]  全文研究框架涵盖主要问题-研究内容-创新点。各个层级间也要有关系，创新点要看起来non trivial
- [ ]  避免与行业常识（比如智能驾驶的已有技术）和大众认识（比如对智能面试系统的设想）冲突

**方法与实验** （解法有效果）

- [ ]  你的创新点及你的工作跟其他工作的区别（改了什么），为什么需要这个创新点（为什么要改），它怎么解决你的问题（怎么用起来），你的方法产生了什么技术效果（有你没你有什么区别），你怎么证明你的方法有效（怎么测试的）
- [ ]  重点讲改了什么，对于用别人的和不相关的就说人家怎么做我们也怎么做就好，不用也罗列一遍。最好是能用对比图表突出我们基于已有工作所改进的地方。
- [ ]  为什么要改，而不是直接用其他场景的方法（比如做的是序列化的工作，那非序列化的方法可以在这里用吗），为什么这个方法不能泛化到其他领域（比如做的riscv的，可以借鉴到其他架构上吗）
- [ ]  怎么用起来，里面的超参数和规则怎么设计，最好是能给个示意图（包括case study图，和整体框架图）
- [ ]  有我们的方法能获得什么好处，能用常识去理解这个技术效果提升的量化程度，最好有个demo表示人家不能做我们能做
- [ ]  怎么测试的，评价指标是这类方法（比如数据集构造）所通用的评价指标嘛，选择对比的baseline是领域SOTA嘛，是要逼近它们（比如对于编译优化逼近手工调优）还是能完全超过它们
- [ ]  对于自己的规则设计，该有的消融实验要有做，以保证自己的实验有效果
- [ ]  对于做出的简化和假设，要么说其他工作也是这么做的，要么说这个多大程度上也能有效，不然会很麻烦

**内容规范** （写作有调理）

- [ ]  论文的大标题，要新颖且包含创新点，而不只是罗列用到的技术。比如若论文题目为《一种面向RISC-V的多级编译优化方法》，则论述里应突出的是我们能打通端到端通路而别人的没打通，不应该只是强调我们如何将多级编译用在RISC-V平台上
- [ ]  论文里的小标题，要让评委看一眼就知道说什么，脱离论文的背景也能相对独立，不要太大
- [ ]  论文里的图，要让评委看一眼就知道说什么，图注要规范，横轴纵轴的标注要符合正常思维
- [ ]  论文里的目录，要让评委看一眼就知道这是合适的，包括章节之间有什么关联，主要问题、研究内容、创新点要互相有逻辑，不要有病句
- [ ]  论文里提到的性能提升，要让评委看一眼就知道是指什么方面的性能提升，跟什么相比，这个程度的提升的量级是多少，能得出什么结论
- [ ]  论文的整体排布，多放图和表格做提炼，每块文字都能很容易跟上下文的图表联系在一起
- [ ]  论文的成果如果能形成demo挂个github链接那最好
- [ ]  写作中回避容易引起评委产生不必要质疑的点，适当用通俗近似的表达来取代精确但拗口的描述

**术语规范** （用词够严谨）
